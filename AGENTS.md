# Flujo de trabajo del proyecto

- Guardar cada avance estable en un commit pequeño, enfocado y descriptivo.
- Ejecutar las pruebas relevantes antes de cada commit que cambie la aplicación.
- Subir los commits a GitHub después de completar y validar cada hito.
- No versionar evidencias reales, archivos de QA, descargas, secretos ni credenciales.
- Mantener `main` siempre utilizable; usar ramas `codex/` para cambios riesgosos o incompletos.
- Publicar una nueva versión del sitio sólo después de validar el mismo commit que se sube.
